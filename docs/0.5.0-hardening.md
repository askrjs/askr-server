# 0.5.0 Server hardening evidence

Preparation baseline: `6dc2c4377e0069ca4a9765d9c40259a7a9ed83f3`.
The version remains 0.4.1 during preparation. This is not publication approval.
API contraction, the complete 0.5 package graph, and final documentation remain
separate release gates.

## Confirmed failures and ownership

One request owns its buffered body, each middleware invocation owns its downstream
response until it transfers or discards it, and a failed error handler propagates
its original failure through enclosing boundaries once.

| Boundary                | Reproducer and resulting behavior                                                                                                                                                                                                                            |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Cached body             | Buffer four bytes, then request a three-byte maximum. The second read rejects with 413; a later four-byte read still reuses the same bytes.                                                                                                                  |
| Oversized stream        | Five bytes with no Content-Length and a four-byte maximum. Throwing or never-settling cancellation hooks cannot stall the 413 result or retain the reader lock.                                                                                              |
| Request abort           | Abort an in-progress, stalled read with throwing or never-settling cancellation. The low-level read rejects with the exact signal reason and releases its lock. A pre-aborted request does not pull its source.                                              |
| Model binding           | JSON, URL-encoded and multipart aborts preserve the original cause in BindingError. Public application dispatch maps unreadable bodies to the existing 400 Problem response.                                                                                 |
| HEAD                    | Suppressed response bodies are canceled once; cancellation failure or a pending cancellation promise cannot replace the HEAD response. Headers survive.                                                                                                      |
| Middleware              | A thrown failure after next(), or before a late downstream response arrives, disposes the discarded stream. Returning the original response, transferring its body, or returning its clone preserves delivered bytes. A replacement response remains usable. |
| Continuation            | Saved next() calls are rejected after completion. Synchronous short circuits retire next() before queued microtasks execute. Existing double-next and ordered composition assertions remain.                                                                 |
| Authorization           | Undefined, null, string and object denial results are rejected before protected handler execution.                                                                                                                                                           |
| Response contracts      | Invalid route and fallback results reach the owning error boundary with corrective TypeErrors, with and without global middleware.                                                                                                                           |
| Error handler           | Invalid onError results reject with a corrective TypeError. Thrown/rejected callbacks propagate the exact failure with one callback invocation, including overlapping requests.                                                                              |
| Probes                  | Undefined and booleans retain their documented meaning. Invalid values report 503 with no-store; an unrelated liveness request remains healthy.                                                                                                              |
| Host rejection tracking | Repeated cached failures remain handled while a caller delays awaiting them. This and the synchronous microtask edge were caught during review of the patch before integration.                                                                              |

Cancellation is best effort: the application does not await an arbitrary
application-owned cancel hook. Middleware that locks a stream itself owns that
reader and must release it. Handler work that never completes cannot be forcibly
terminated by the Web Request/Response core.

## Retained assertions and characterization

The review inspected assertion bodies, rather than relying on test names:

- Routing: literal/parameter/wildcard precedence, equal-priority order, static
  descendants, empty named wildcards, method aggregation, explicit HEAD/OPTIONS,
  malformed parameter escapes and capture isolation.
- Binding and headers: JSON/form/multipart precedence, repeated values and cookie
  order, mixed-case media types, consumed/cached streams, prototype-shaped keys,
  native source failures, application and route body limits.
- Policy: one auth resolution, request-local auth identity, denial before route
  middleware/upgrade, CSRF form-buffer reuse, encoded redirect allowlists, invalid
  redirect cookie suppression, and rate-limit/CORS order.
- Metadata: escaped HTML/JSON-LD and control sanitation; five new characterization
  cases retain ASCII and Latin-1 raw headers and round-trip Japanese, emoji and a
  40,000-character payload through base64url-v1. The prior Unicode fix remains
  a regression target; these cases did not identify a new encoding defect.
- Streams: SSE write quotas and serialization recovery, heartbeat coalescing,
  abort cleanup, deferred SSR chunks, streamed style-prefix cancellation.
- Protocols: MCP negotiation, Origin/Host/media checks, malformed initialization,
  bounded session capacity/expiry/deletion, tool/schema/auth failures, invalid
  cursors and URI escapes; OpenAPI duplicate/invalid metadata and references,
  required/malformed input, source-prefixed issues and opt-in response validation.

Coverage remains partial for the broader MCP/resource/prompt and auth-helper
surfaces. Adapter-conformance runner tests exercise faulty exercise functions,
deadlines and cancellation; they do not prove real socket/listener cleanup.
That transport qualification belongs to the Node adapter pass. The generated
website and Vite decoder/real-HTTP header-size parity remain final candidate
checks. In particular, the large metadata unit case makes no claim that an HTTP
server accepts headers of that size.

## Validation and costs

Node 24.21.0: npm ci; npm run fmt -- --check; npm run check.
The gate checks source and benchmark types, unit coverage, strict built
declarations, publint, packed files and an ordinary installed tarball. The latter
imports all nine current entrypoints and executes HEAD/replacement cleanup,
denial/probe guards, error-handler failure and request-abort binding. Unexported
implementation paths remain inaccessible.

Whole-source coverage measured approximately 89% lines, 88% statements, 81%
branches and 87% functions, with explicit regression floors. Affected-file floors
are stronger where established: application 96% lines/branches, body reader 91%
lines and 100% functions, dispatch 94% lines/89% branches, and the private disposer
100% lines/functions. Coverage is not proof of every policy combination.

The prior route-array benchmark fixtures silently dispatched 404s. The corrected
fixtures register a router and assert actual status/bound values before timing;
benchmark sources now participate in typechecking. Baseline timing uses the same
corrected fixtures and dependency/toolchain set as the candidate.

Local diagnostic pairs measured approximately 0.5-0.6 microseconds more for JSON/form
binding and 0.1-0.15 microseconds more for two-middleware dispatch. Body reads now
register/remove cancellation and race stalled work; middleware tracks and disposes
owned downstream responses. These are correctness costs, with no optimization,
throughput or capacity claim. The causal path stays explicit, with no cache or
alternate fast path added. Raw results and exact candidate provenance belong in
the maintainer review packet.

The production dependency lock entries are unchanged. Compatible development
tooling updates remove the reported source-map-js/tinypool advisories; npm audit
reported zero findings after the update.
